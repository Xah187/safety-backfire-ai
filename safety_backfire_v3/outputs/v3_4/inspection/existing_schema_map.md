## 1. Existing In-Repo Schemas

### 1.1 V3.1 Frozen Schemas (`outputs/v3_1_frozen/`)
The repository previously established JSON Schemas conforming to JSON Schema Draft 2020-12 for ontology and risk events:
* `backfire_schema.json`: Formalized safety backfire conditions, safety margins, and time-to-collision (TTC) bounds.
* `hazard_schema.json`: Structured hazard classifications (forklift-pedestrian proximity, blind corner incursion).
* `risk_schema.json`: Categorized risk decisions (`CONFIRMED_DANGER`, `CAUTION`, `CANDIDATE_REVIEW`, `SUPPRESSED_OPERATOR`).
* `entity_schema.json` & `ontology_schema.json`: Spatial and kinematic definitions of industrial entities.

### 1.2 Perception & Detection Data Formats (V3.3.3)
In the execution scripts (`execute_run_003_nvidia_warehouse.py` and `execute_run_004_nvidia_warehouse_027.py`), detections are generated by YOLOv8/YOLO26 and serialized as nested dictionaries:
```python
detection = {
    "frame_idx": int,
    "timestamp_s": float,
    "bbox_xyxy": [float, float, float, float],
    "foot_point_px": [float, float],
    "confidence": float,
    "class_id": int,
    "class_name": str,  # "person" or "forklift"
    "metric_dist_m": float,  # Derived via ground homography
    "k_H": float,           # Computed via Model H
    "occlusion_state": str   # "NONE", "PARTIAL", "HEAVY" (proxy derived)
}
```

### 1.3 Tracking Data Formats (V3.3.3)
Tracking outputs from ByteTrack are serialized in `track_topology.json` and per-camera summaries:
```python
track_record = {
    "track_id": int,
    "start_frame": int,
    "end_frame": int,
    "total_detections": int,
    "mean_distance_m": float,
    "min_distance_m": float,
    "max_distance_m": float,
    "mean_confidence": float,
    "trajectory_points": [[float, float, float], ...] # [frame, x_px, y_px]
}
```

### 1.4 Geometry & Calibration Formats (V3.3.3)
Extrinsics and intrinsics are derived from JSON sensor files (`sensor.json`):
* `extrinsic_3x4`: $[R \mid t]$ matrix (world-to-camera).
* `intrinsic_3x3`: Camera matrix $K$ containing focal lengths ($f_x, f_y$) and principal point ($c_x, c_y$).
* Derived fields:
  * Camera center in world coordinates: $C = -R^T t$.
  * Optical axis vector in world frame: $v_{\text{opt}} = R^T [0, 0, 1]^T$.
  * Depression angle: $\theta_{\text{dep}} = -\arcsin(v_{\text{opt}}[2])$.
  * Ground-plane homography: $H_{\text{img}\to\text{ground}} = (P_{:, [0, 1, 3]})^{-1}$, where $P = K [R \mid t]$.

## 2. V3.4 Schema Delta & Requirements Mapping

The V3.4 milestone formalizes **independent human ground truth and external physical evidence**. Previous ad-hoc and simulation-derived representations are replaced by explicit, strictly validated JSON schemas:

| Schema Name | Target File in V3.4 | Primary Key / Required Fields | Key V3.4 Enhancements |
| :--- | :--- | :--- | :--- |
| **Detection GT** | `schemas/v3_4/detection_gt.schema.json` | `facility_id`, `camera_id`, `frame_id`, `timestamp`, `object_id`, `class`, `bbox`, `foot_point`, `visibility`, `occlusion` | Mandates human/independent annotation; strict pixel boundary validation; explicit occlusion levels; prohibition of model-derived labels. |
| **Trajectory GT** | `schemas/v3_4/trajectory_gt.schema.json` | `facility_id`, `trajectory_id`, `object_id`, `timestamp`, `world_x`, `world_y`, `world_z`, `zone_id` | Full 3D metric ground-plane trajectory tracking across persistent identity labels; zone mapping. |
| **Lux Telemetry** | `schemas/v3_4/lux_telemetry.schema.json` | `facility_id`, `sensor_id`, `timestamp`, `lux`, `sampling_rate_hz`, `measurement_uncertainty`, `calibration_reference`, `location` | Replaces simulated/missing lux with NIST-traceable physical sensor telemetry; explicit `"UNKNOWN"` for missing values. |
| **Camera Survey** | `schemas/v3_4/camera_survey.schema.json` | `facility_id`, `camera_id`, `camera_height_m`, `optical_axis_vector`, `depression_angle_deg`, `roll_deg`, `yaw_deg`, `intrinsics`, `distortion`, `extrinsics`, `coordinate_system`, `survey_timestamp`, `survey_source` | Replaces virtual transform nodes with physical surveying records (laser rangefinders, total stations). |

## 3. Strict Semantic Policies for V3.4 Schemas
1. **Explicit Support for `UNKNOWN`**: Nullable fields must explicitly serialize `"UNKNOWN"` rather than substituting `0.0`, `-1`, or `null`.
2. **Zero Default Substitution**: If sensor telemetry or ground truth is missing, it must be declared missing.
3. **No Model-Derived Ground Truth**: Outputs from YOLO, ByteTrack, or any automated model cannot be masqueraded as Ground Truth.
