# V3.2 — Event-Level Validation: Primary Safety Metric Report

## 1. Executive Summary

In automated industrial safety, object detection benchmarks (mAP, bounding box IoU) are fundamentally insufficient. A computer vision model may detect 99% of people and forklifts on individual frames, yet fail as a safety system if it fragments alerts, triggers 50 false alarms per hour, or delays alarm confirmation until after physical impact.

**The primary metric of Safety Backfire AI V3.2 is EVENT-LEVEL VALIDATION.** An event is defined as a continuous physical hazard episode with defined temporal onset, confirmation, peak danger, and resolution phases.

Evaluated over $2.5\,\text{hours}$ of continuous industrial warehouse monitoring encompassing $N = 50$ ground truth safety events:
- **Event Precision:** $0.9400$ ($94.00\%$) [$47 / 50$ asserted events]
- **Event Recall:** $0.9400$ ($94.00\%$) [$47 / 50$ ground truth events]
- **Event F1 Score:** $0.9400$ ($94.00\%$)
- **False Events per Operational Hour:** $1.20\,\text{events/hour}$ [$3$ false alarms in $2.5\,\text{hours}$]
- **Missed Dangerous Events per Hour:** $1.20\,\text{events/hour}$ [$3$ missed events in $2.5\,\text{hours}$]
- **Time-to-Detection (P95):** $0.145\,\text{seconds}$ ($4.35\,\text{frames}$)
- **Time-to-Confirmation (P95):** $0.171\,\text{seconds}$ ($5.13\,\text{frames}$)

## 2. Event Taxonomy & Ground Truth Correspondence

To eliminate ambiguous scoring, V3.2 formalizes six mutually exclusive event outcomes:

| Event Outcome Type | Definition | Measured Count |
| :--- | :--- | :---: |
| **True Positive Event (TP)** | AI event correctly matches a human-annotated hazard episode with temporal $\text{IoU} \ge 0.50$ and identical hazard classification. | **47** |
| **False Positive Event (FP)** | AI triggers a confirmed alert episode with zero corresponding physical danger in ground truth. | **3** |
| **Missed Event (FN)** | Ground truth hazard episode transpires without the AI confirming an alert. | **3** |
| **Fragmented Event** | A single continuous physical hazard is fragmented by the AI into $\ge 2$ disconnected alert episodes (`FAIL-41`). | **2** |
| **Duplicated Event** | Multiple overlapping AI event IDs are generated for the same physical entity interaction. | **1** |
| **Partial Event** | AI detects the hazard but truncates it ($\text{temporal IoU} < 0.30$), firing late or terminating early. | **0** |

## 3. Temporal Latency & Lifecycle Characteristics

Safety events must fire rapidly while avoiding premature termination:

```text
========================================================================================
Event Lifecycle Phase                Mean Duration         P95 Duration     Safety Goal
========================================================================================
Time-to-Detection (TTD)              0.109 s (3.27 frames) 0.145 s          <= 0.200 s
Time-to-Confirmation (TTC_confirm)   0.141 s (4.23 frames) 0.171 s          <= 0.250 s
Time-to-Resolution (TTR)             1.018 s (30.5 frames) 1.250 s          <= 1.500 s
Mean Active Alert Duration           3.590 s               5.400 s          Continuous
========================================================================================
```

### 3.1 Timing Analysis
1. **P95 Confirmation Latency ($171\,\text{ms}$):** At $30\,\text{fps}$, an oncoming forklift traveling at maximum warehouse speed ($3.0\,\text{m/s}$) advances only $0.51\,\text{m}$ between physical hazard emergence and confirmed safety alarm.
2. **Resolution Dwell Time ($1.018\,\text{s}$):** When clearance is restored, the alert persists for approximately 30 frames. This prevents rapid toggling if the entity momentarily pauses at the hazard boundary.

## 4. Decoupling Detection from Event-Level Safety

A detection can be correct while the event decision is catastrophic:

```text
Example 1: High Detection, Failed Event
  - Frame 100: Person detected (IoU = 0.85) -> NO ALERT
  - Frame 101: Forklift detected (IoU = 0.89) -> NO ALERT
  - Frame 102: Track drop -> NO ALERT
  - Frame 103: New Track -> ALERT FIRES
  Outcome: High mAP on static frames, but event was delayed and fragmented.

Example 2: Perfect Spatial Perception, False Safety Claim
  - Frame 200: Pedestrian detected inside designated green walkway.
  - Frame 200: Forklift detected in travel lane 1.2m away.
  - Static Proximity Rule: Flags COLLISION ALERT.
  Outcome: False positive event because protective bollard separates lanes.
```

By elevating **Event F1** and **False Events per Hour** to primary status, V3.2 ensures that the AI system is judged on end-to-end operational safety rather than surrogate computer vision benchmarks.
