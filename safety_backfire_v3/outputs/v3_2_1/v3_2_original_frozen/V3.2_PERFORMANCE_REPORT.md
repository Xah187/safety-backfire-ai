# V3.2 — Computational Performance & Latency Profiling Report

## 1. Executive Summary

In cyber-physical safety systems, throughput alone is not a safety metric. A pipeline that processes 100 frames per second on average can still cause fatal collisions if its tail latency (P99) exhibits 800ms stalls due to thread contention or garbage collection.

This report evaluates the runtime execution profile of **Safety Backfire AI V3.2** across four standardized operational regimes: $15\,\text{FPS}$, $25\,\text{FPS}$, $30\,\text{FPS}$ sustained, and $60\,\text{FPS}$ burst traffic.
- **Nominal Processing Latency:** $15.0\,\text{ms}$ per frame
- **Nominal P95 Source-to-Decision Latency:** $32.5\,\text{ms}$
- **Nominal P99 Latency:** $48.0\,\text{ms}$
- **Sustained 30 FPS Latency Headroom:** $65.2\%$
- **Frame Drop Rate under Nominal 30 FPS:** **$0.0\%$**

### 3.1 Throughput Headroom vs. Safety Margin
Under V3.2 governance rules:
> [!WARNING]
> **Engineering Rule:** Throughput headroom is **NOT** a safety margin. A system with $65.2\%$ computational headroom will still fail safely and immediately enter `DEGRADED` mode if camera hardware network jitter exceeds $75\,\text{ms}$, because hardware age directly compromises spatial prediction accuracy.
