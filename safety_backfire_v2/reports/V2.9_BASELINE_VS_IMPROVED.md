## 3. Causal Evidence of Implemented Fixes (P0 / P1)

### Fix 1: Multi-Vehicle Association & Evidence Decoupling
* **Root Cause:** In `core/operator_relation_v2.py`, `relations.append()` was outside the forklift loop, causing only the last forklift to be recorded and cross-contaminating evidence.
* **Before:** In a scene with 1 Person and 2 Forklifts (one near, one far), querying the near forklift returned `None`, while the far forklift inherited 100% overlap evidence.
* **After:** Pairwise relations are recorded for every `(person, forklift)` permutation. Lookups by `(person_id, forklift_id)` return deterministic, unpolluted relations.
* **Regression Test:** Verified via `validation/v2_9/test_multi_object_stress.py` (Passed 5/5).

### Fix 2: 2D Closest Point of Approach (CPA) / Miss-Distance TTC Filter
* **Root Cause:** In `core/kinematics.py`, 1D range-rate TTC flagged any decreasing distance ($-\dot{d} > 0$) as an impending collision, causing false emergency alerts on safe 90-degree crossings.
* **Before:** Forklift and pedestrian on orthogonal paths with a 5.66m clearance produced `ttc_status: VALID`, `TTC = 8.67s` (False Collision Alert).
* **After:** Trajectory extrapolated to closest point of approach:
  $$t_{\text{cpa}} = -\frac{\mathbf{r}_0 \cdot \Delta\mathbf{v}}{\|\Delta\mathbf{v}\|^2}, \quad \text{Miss-Distance} = \|\mathbf{r}_0 + \Delta\mathbf{v} \cdot t_{\text{cpa}}\|$$
  Since $\text{Miss-Distance} = 5.66\text{m} > 1.8\text{m}$, the engine returns `ttc_status: "CROSSING_CLEARED"`, `ttc_sec: None`.
* **Regression Test:** Verified via `validation/v2_9/test_ttc_cpa_geometry.py` (Passed 2/2).

### Fix 3: Man-Down / Fallen Worker Protection
* **Root Cause:** In `core/observation_gate.py`, Rule 3 rejected all detections with aspect ratio $< 1.0$ as non-human, erasing fallen, injured, or crouching workers.
* **Before:** Fallen worker (aspect ratio $0.44$, zero keypoints) declared `INVALID` and `safety_eligible = False`.
* **After:** Horizontal detections on the floor away from vehicle chassis are preserved as `ObservationValidity.WEAK` with `safety_eligible = True` (`reason: "Fallen or crouching worker candidate (Man Down)"`).
* **Regression Test:** Verified via `validation/v2_9/test_ttc_cpa_geometry.py`.

### Fix 4: Schema Parity & RiskEngine Attribute Restoration
* **Root Cause:** `InteractionEventV2` dropped `median_distance_m` and `peak_approach_speed`, causing `RiskEngine.calculate_risk_exposure()` to crash with `AttributeError`.
* **Before:** Any call to `RiskEngine` on V2.8+ events crashed the interpreter.
* **After:** `median_distance_m` and `peak_approach_speed` computed dynamically in `InteractionEventV2.end()` and exposed via `to_dict()`; `RiskEngine` hardened with safe attribute access.
* **Regression Test:** Verified via `validation/v2_9/test_numerical_stability.py` (Score calculated: `9.09`).

### Fix 5: Removal of Speed-Based Operator Shortcut
* **Root Cause:** `generate_v2_8_5_video.py` used `p.get("speed_m_s", 0.0) > 0.8` as a heuristic for vehicle riding, falsely suppressing fast-walking pedestrians.
* **Before:** Pedestrian running at $1.5$ m/s classified as `OPERATOR_ON_VEHICLE`.
* **After:** Operator status requires verified geometric/pose relation from `OperatorVehicleRelationEngineV2`.

### Fix 6: Unbounded Velocity Clamping
* **Root Cause:** Tracker ID swaps jumping across the screen produced unphysical velocities ($> 600$ m/s) without bounding.
* **Before:** Velocity reached Mach 2 on ID swaps.
* **After:** Clamped to maximum warehouse equipment physical limit ($10.0$ m/s $\approx 36$ km/h).

## 4. Failures Deliberately Left Unresolved

In accordance with strict engineering standards, the following 4 structural limitations were **not** patched with fragile heuristics and are formally documented for architectural redesign:

1. **FAIL-07: Event Fragmentation Across Tracker ID Switches:**
   * *Status:* **UNRESOLVED.**
   * *Justification:* When ByteTrack loses an object during extended occlusions and creates a new track ID (e.g. P10 $\to$ P11), the event engine closes the active event and opens a new candidate event. Resolving this without visual re-identification (ReID appearance feature embeddings or bipartite spatio-temporal graph matching) would require arbitrary distance thresholds that cause track identity corruption in dense scenes.
2. **FAIL-08: Sequential Inference Throughput Bottleneck (15.8 FPS vs 25 FPS Live):**
   * *Status:* **UNRESOLVED (Core Architectural Task).**
   * *Justification:* Detector (30 FPS) and Pose (34 FPS) executed sequentially in a single synchronous thread cannot achieve 25 FPS ($33\text{ms} + 29\text{ms} = 62\text{ms} \to 16\text{ms}$ over budget). Solving this requires an asynchronous multi-threaded architecture where Pose runs on a worker thread at a reduced stride (e.g. 5–8 Hz), while the main thread tracks at 25 Hz.
3. **FAIL-10: Elevated Operator Cabin Homography Radial Distortion:**
   * *Status:* **UNRESOLVED.**
   * *Justification:* Planar homography assumes all projected pixels contact the floor ($Z=0$). A driver standing in a raised cabin or on an EPJ platform is $0.5$m–$1.0$m above the floor, displacing their projected position radially outward by up to $2.5$m. True rectification requires 3D camera extrinsics and a 3D bounding box / ray-casting ground-plane intersection model.
4. **FAIL-12: Centralized Configuration Schema Migration:**
   * *Status:* **UNRESOLVED.**
   * *Justification:* Hardcoded thresholds (`0.35`, `0.25 m/s`, `15 frames`, `1.5m/3.0m`) remain scattered across modules. A dedicated schema refactoring (e.g. Pydantic-based configuration model) is scheduled for the foundational phase of V3.0.

## 7. Recommended Next Engineering Phase: V3.0 Core Foundation

Based on reproducible evidence, the project is **not** ready for a customer dashboard or user-facing web interface. The immediate engineering priority must be:

> **V3.0 Core Foundation: Asynchronous Pipeline Architecture, ReID Track Stitching & Centralized Schema Engine**

### Specific Objectives for Next Phase:
1. **Asynchronous Multi-Threaded Engine:** Decouple video decoding, detection, tracking, and pose estimation into separate worker threads, allowing the pipeline to comfortably exceed 30+ FPS live processing.
2. **Pose Stride Decimation:** Run pose estimation only on active person bounding boxes at 5–10 Hz, interpolating joints via Kalman state to reduce compute load by $>60\%$.
3. **ReID Feature Embedding:** Integrate lightweight visual appearance features into ByteTrack to maintain identity across occlusions $>15$ frames, solving event fragmentation.
4. **Pydantic Configuration System:** Migrate all magic numbers and thresholds from code into a strictly validated, centralized configuration schema.
